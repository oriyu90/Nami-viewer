## 1. 要望の整理

| # | 要望 | 実装上の解釈 |
|---|---|---|
| R1 | Windows 10/11 64bit、内部が Rust | Rust 製ネイティブアプリ。UI 層以外のロジック（デコード・解析・再生・出力）はすべて Rust |
| R2 | mp3 / wav / flac など 5 秒以上の音声入力 | 5.0 秒未満は明示エラー。mp3 / wav / flac に加え ogg(vorbis) も受付 |
| R3 | 1 レーン DAW 風の全体波形（時間軸） | 最上段「Master」レーン。時間ルーラー＋波形＋再生ヘッド |
| R4 | 2 行目以降に最大 4 列の周波数成分別波形 | バンドレーン最大 4 本（Low / Low-Mid / Mid-High / High）。帯域は設定で変更可 |
| R5 | 上部に再生・停止・再生バー。簡易プレイヤー | トランスポートバー（再生/一時停止・停止・シークバー・音量・時間表示） |
| R6 | 最上段レーンの右クリックで BPM・小節設定、目盛り表示 | コンテキストメニュー→テンポ設定ダイアログ。小節/拍グリッドを描画 |
| R7 | 小節開始位置をレーン内で調整 | ルーラー上の「1」フラグをドラッグ、またはダイアログで数値入力 |
| R8 | 2 行目以降の各レーン右クリック→拍出力。未設定時は押せない | 各バンドレーンのメニューに「拍のずれを CSV 出力」。テンポ未設定時は disabled |
| R9 | 各拍が拍内で前からどれだけずれているかを数学的に算出し CSV | 拍グリッドと帯域別オンセット検出の差分（ms / 拍比）を CSV 化 |
| R10 | 操作状況を JSON で入出力 | プロジェクト JSON（音声パス・テンポ・表示・バンド・再生位置・UI 設定） |
| R11 | 設定（各種）・日本語/英語・ダーク/ホワイト・スケール変更 | 設定モーダル。言語・テーマ・UI 倍率・解析・再生・出力の各設定 |
| R12 | ポータブル zip | 単一 exe（アセット埋め込み）＋ README ＋ 仕様書を zip 化。インストーラ不要 |

## 2. 技術選定

### 2.1 GUI 方式の比較

| 候補 | 長所 | 短所 | 判定 |
|---|---|---|---|
| **Tauri 2 (Rust + WebView2)** | UI を HTML/CSS/Canvas で高精度に構築。Rust 側に音声/DSP を集中。アセットは exe に埋め込み可能。WebView2 は Win10/11 に標準搭載 | WebView2 ランタイムに依存（Win11 は標準、Win10 も Edge 更新で通常導入済み） | **採用** |
| eframe / egui（純 Rust） | 単一 exe で完全自己完結。依存ゼロ | DAW 風の繊細な描画・タイポグラフィ・多言語レイアウトを都度自前実装する必要があり、UI 品質と検証コストが高い | 不採用 |
| Slint | 宣言的 UI、ネイティブ描画 | 波形キャンバスや複雑なコンテキストメニューは結局 Rust 側の描画実装。エコシステムが小さめ | 不採用 |
| Iced | 純 Rust、Elm 型 | 大規模カスタム描画とアクセシビリティ対応の実績が薄い | 不採用 |

**採用理由**: 本アプリの本質は「Rust による音声解析エンジン」＋「情報密度の高い計測 UI」。後者を Web 技術で作ることで、波形・グリッド・多言語・テーマ・スケールを短時間かつ高品質に実装でき、ブラウザでの自動 UI 検証も可能になる。Rust 側は Tauri のコマンドとして公開し、UI から完全に分離する。

### 2.2 Rust クレート

| 用途 | クレート | 選定理由 |
|---|---|---|
| アプリシェル / IPC | `tauri` 2.x | WebView2 埋め込み、静的アセット同梱、単一 exe 化 |
| 音声デコード | `symphonia` 0.5 (mp3, wav, flac, ogg/vorbis, pcm) | 純 Rust・クロスフォーマット・シーク不要の一括デコードに十分な速度 |
| FFT | `rustfft` 6 | 高速・実績多数・pure Rust |
| 再生 | `cpal` 0.16 (WASAPI) | 低遅延。自前のリング不要なメモリ再生＋Atomic 位置管理で正確な再生ヘッド同期 |
| ファイルダイアログ | `rfd` 0.15 | OS ネイティブダイアログ。プラグイン配線不要 |
| 設定保存先 | `dirs` 6 | `%APPDATA%` 解決。ポータブルモードでは exe 隣接 |
| シリアライズ | `serde` / `serde_json` | プロジェクト JSON・設定 JSON・IPC |
| Windows API | `windows-sys`（任意） | WebView2 不在時のメッセージボックス |

### 2.3 再生方式の考察

`rodio` の Sink でも再生は可能だが、シーク位置と UI 再生ヘッドの厳密な一致、帯域解析用のサンプル列再利用、デバイス非対応サンプルレート時のフォールバックを考えると、**デコード済みステレオバッファを cpal コールバックで直接読む方式**が最も単純で確実。

- `cpal::Stream` は環境により `Send` でないため、**専用オーディオスレッドが Stream を所有**し、`mpsc` でコマンド（Load / Play / Pause / Seek / Volume / Stop）を受ける。
- 再生位置・再生中フラグ・音量は `Arc<AtomicU64/U32>` で共有し、UI はロックなしで 30Hz ポーリング。
- デバイスがソースのサンプルレートを拒否した場合は 48kHz に線形リサンプルして再生（解析は原音レートで実施）。

### 2.4 解析方式の考察

要件は「周波数別の波形」と「拍ごとのずれ」の 2 つ。STFT の全マグニチュードを保持すると 5 分で 100MB 超になるため、**対数周波数バンド（96 帯域）のパワー行列**に集約して保持する。

- FFT サイズ: 1024 / 2048 / 4096（設定可、既定 2048）。Hann 窓、ホップ 512（44.1kHz で 11.6ms）。
- 96 本の対数帯域（20Hz–20kHz）に FFT ビンを集約。メモリは 5 分で約 10MB。
- 任意の帯域設定（最大 4 本）は 96 バンドの部分和で即時再計算 → 設定変更が軽い。
- 表示用エンベロープ: 帯域内パワー和の平方根を 99 パーセンタイルで正規化。
- オンセット強度: 帯域内ログパワーの正の差分（spectral flux 相当）を平滑化・正規化。
- 拍のずれ: 拍グリッド時刻 ±許容幅の中でオンセット強度最大のフレームを探索し、放物線補間でサブフレーム精度の時刻を求める。ずれ = 検出時刻 − 拍開始時刻。

この方式は「拍の頭で鳴る打楽器」に対して頑健で、帯域ごとに異なる楽器（キック/スネア/ハイハット）のずれを個別に評価できる。

### 2.5 ポータビリティ

- `tauri.conf.json` の `frontendDist: "../ui"` により UI アセットは exe に埋め込まれる（実行時ファイル不要）。
- ビルドは `cargo build --release` のみ（Node.js 不要）。
- 設定は既定で `%APPDATA%\com.namivision.app\settings.json`。`--portable` 起動または exe 隣の `portable.txt` で `.\data\settings.json` を使用。
- WebView2 不在環境では起動時に日本語/英語のメッセージボックスで案内（クラッシュさせない）。

## 3. 設計計画（工程）

| 工程 | 内容 | 成果物 |
|---|---|---|
| P1 | 要望分析・技術調査 | 本ファイル |
| P2 | 設計仕様確定（UI・IPC・データ形式・アルゴリズム・試験計画） | `docs/02_設計仕様書.md` |
| P3 | Rust コア実装（デコード / DSP / 再生 / CSV / JSON / 設定）＋単体テスト | `src/*.rs`, `cargo test` |
| P4 | UI 実装（レイアウト / 波形描画 / 操作 / i18n / テーマ / スケール）＋モック環境 | `ui/*` |
| P5 | 統合・ビルド・実機起動確認 | `NamiVision.exe` |
| P6 | デバッグ（安定性・UI 完全性）／ブラウザ QA・実アプリ QA | QA レポート、修正 |
| P7 | ポータブル zip 化・最終検証 | `dist/NamiVision_0.1.0_windows-x64_portable.zip` |

### 品質ゲート

1. `cargo test` 全通過、`node --test` 全通過。
2. 5 秒未満・非対応形式・破損ファイル・音声消失プロジェクトでクラッシュしない。
3. 1440 / 1024 / 900px 幅、倍率 80–150%、ダーク/ライト、日英でレイアウト破綻・文字切れがない。
4. テンポ未設定時に CSV 出力が押せない。設定後は CSV が生成され、値が数式と一致する。
5. 実アプリで音声読込→再生→シーク→CSV→JSON 保存/読込が一巡する。
