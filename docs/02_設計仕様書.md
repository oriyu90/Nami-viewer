# NamiVision — 設計仕様書

版: 1.0 / アプリ版: 0.1.0 / 対象: Windows 10 22H2・11 x64

---

## 1. 概要

NamiVision は、音声ファイルの全体波形と最大 4 本の周波数帯域波形を DAW 風に表示し、BPM・拍子・小節開始位置から作る拍グリッドに対して、各帯域の音の立ち上がりが「拍の頭からどれだけずれているか」を算出して CSV 出力する計測アプリ。簡易音楽プレイヤーとしても使える。

- コア: Rust（デコード / 解析 / 再生 / CSV / JSON / 設定）
- UI: HTML + CSS + Vanilla JS（ES Modules）+ Canvas 2D（Tauri WebView2）
- 配布: 単一 exe のポータブル zip

## 3. データモデル

### 3.1 音声メタデータ `AudioMeta`

```json
{
  "path": "C:\\music\\song.flac",
  "fileName": "song.flac",
  "format": "flac",
  "sampleRate": 44100,
  "channels": 2,
  "durationSec": 213.45,
  "bitDepth": 16
}
```

- 対応拡張子: `.mp3 .wav .flac .ogg .oga`（大文字小文字不問）。他の拡張子は `ERR_UNSUPPORTED_FORMAT`。
- 5.0 秒未満は `ERR_AUDIO_TOO_SHORT`（params: `min`, `actual`）。
- 60 分超は `ERR_AUDIO_TOO_LONG`。20 分超は警告（`warning: "longAudio"`）を返すが処理続行。

### 3.2 解析結果 `AnalysisResult`

```json
{
  "meta": { ...AudioMeta },
  "peakBucketsPerSecond": 500,
  "peaksMin": [0.0, -0.12, ...],
  "peaksMax": [0.0, 0.44, ...],
  "frameHopSec": 0.011609977,
  "frameCount": 18390,
  "logBandCount": 96,
  "logBandEdgesHz": [20.0, 21.7, ...],
  "bands": [
    {
      "index": 0,
      "label": "Low",
      "lowHz": 20,
      "highHz": 250,
      "color": "#4FC3F7",
      "envelope": [0.0, 0.12, ...],
      "onset": [0.0, 0.03, ...]
    }
  ],
  "analysisMs": 812,
  "warning": null
}
```

- `peaksMin` / `peaksMax`: モノラル化したサンプルの 2ms 区間 min/max（長さ = ceil(duration*500)）。値域 -1.0〜1.0。
- `envelope` / `onset`: フレーム数と同じ長さ、0.0〜1.0 に正規化。
- 帯域設定は 4 本固定（設定で帯域境界を変更、本数は 1〜4）。`bands` は現在の設定順。
- `logBandEdgesHz` は 97 要素（96 バンドの境界）。

### 3.3 テンポ設定 `Tempo`

```json
{
  "enabled": true,
  "bpm": 128.0,
  "beatsPerBar": 4,
  "barStartSec": 0.42,
  "subdivision": 2,
  "showGrid": true,
  "snapToGrid": false
}
```

- `bpm`: 20.0〜400.0。`beatsPerBar`: 2/3/4/6/8。`barStartSec`: 0.0〜duration。`subdivision`: 1/2/4（拍の分割表示）。
- `enabled=false`（初期値）のときグリッド非表示・CSV 出力不可。

### 3.4 プロジェクト JSON `ProjectFile`（schema v1）

```json
{
  "schema": "namivision.project",
  "version": 1,
  "appVersion": "0.1.0",
  "savedAt": "2026-10-29T12:34:56Z",
  "audio": { "path": "C:\\music\\song.flac", "fileName": "song.flac", "durationSec": 213.45 },
  "tempo": { ...Tempo },
  "view": { "zoomPxPerSec": 96.0, "scrollSec": 12.5, "selectedBand": 0, "followPlayhead": true },
  "bands": [
    { "lowHz": 20, "highHz": 250, "color": "#4FC3F7" },
    { "lowHz": 250, "highHz": 1000, "color": "#7BD88F" },
    { "lowHz": 1000, "highHz": 4000, "color": "#FFC857" },
    { "lowHz": 4000, "highHz": 16000, "color": "#FF7A8A" }
  ],
  "playback": { "positionSec": 12.3, "volume": 0.8 },
  "ui": { "lang": "ja", "theme": "dark", "scale": 1.0 }
}
```

- 読み込み時: JSON 構文・`schema`・`version` を検証。`version > 1` は `ERR_PROJECT_VERSION`。
- 音声が見つからない場合: 設定（テンポ・表示・バンド・UI）は復元し、`audioMissing: true` を返す。UI は「音声を再選択」バナーを表示し、再選択後もテンポ等を保持する。
- 未知フィールドは無視（前方互換）。欠損フィールドは既定値で補完。

{

## 4. アルゴリズム仕様

### 4.1 デコード

1. 拡張子チェック → 5 秒判定はデコード後 `duration` で行う（メタだけでは不正確なため）。
2. symphonia で全パケットをデコード。出力は f32 インターリーブ。
3. 解析用モノラル: `mono[i] = Σ ch / channels`。
4. 再生用: 1ch は 2ch 複製、2ch はそのまま、3ch 以上は先頭 2ch を使用（L/R）。
5. サンプルレートは原音のまま保持。

### 4.2 ピーク列

`bucket = floor(sample_index / sample_rate * 500)`。各バケットの min/max を格納。
バケット数 `n = max(1, ceil(duration * 500))`。

### 4.3 STFT と対数バンド

- 窓: Hann、`N = fftSize`、ホップ `H = 512`（固定）。
- フレーム数 `F = 1 + floor((mono.len().saturating_sub(N)) / H)`（mono が N 未満なら 1 フレームにゼロ詰め）。
- フレーム時刻 `t_f = f * H / sample_rate`。
- 各ビン `k` の周波数 `f_k = k * sample_rate / N`。DC とナイキスト超は除外。
- 96 本の対数バンド境界: `e_j = 20 * (20000/20)^(j/96)`、`j=0..96`（`e_0=20`, `e_96=20000`）。
- バンド `j` のパワー `P[f][j] = Σ_{k: e_j <= f_k < e_{j+1}} |X[k]|^2`（該当ビンなしなら最近傍 1 ビン）。
- 保存: `P` を f32 で `F × 96`。メモリ上限のため 20 分超は警告。

### 4.4 帯域エンベロープ（表示）

帯域 `b`（`[low, high)`）に含まれる対数バンド集合 `J_b` について

```
E_b[f] = sqrt( Σ_{j∈J_b} P[f][j] / |J_b| )
env_b[f] = clamp(E_b[f] / p99(E_b), 0, 1) ** 0.75
```

`p99` は 0 の場合は 1 とする。`** 0.75` は小音量の視認性のための圧縮。

### 4.5 オンセット強度

```
L_b[f] = ln( Σ_{j∈J_b} P[f][j] + 1e-12 )
D_b[f] = max(0, L_b[f] - L_b[f-1])          (f=0 は 0)
S_b = 移動平均(3) した D_b
onset_b[f] = clamp(S_b[f] / p99(S_b), 0, 1)
```

`onsetSensitivity` 設定は CSV 出力時の検出しきい値に反映する:
`threshold = 0.30 - 0.25 * sensitivity`（感度 0→0.30、1→0.05）。

### 4.6 拍グリッド

- `beatDur = 60 / bpm`
- `barDur = beatDur * beatsPerBar`
- 拍番号 `k`（整数、`barStartSec` の拍を 0 とする）の時刻 `T_k = barStartSec + k * beatDur`
- 小節番号 `bar = floor(k / beatsPerBar) + 1`、拍内位置 `beatInBar = (k mod beatsPerBar) + 1`（負数は Euclidean mod）
- 表示は `T_k ∈ [0, duration]` の範囲。小節線は `k mod beatsPerBar == 0`。サブディビジョン線は `beatDur / subdivision` 間隔。

### 4.7 拍のずれ算出（CSV の数学的定義）

帯域 `b`、拍 `k` について:

1. 探索窓 `W = tolerance * beatDur`（`tolerance = 0.45` 固定）。窓は**遅延補正後のオンセット時刻**で定義し、生フレーム時刻では `[T_k - W - latency, T_k + W - latency] ∩ [0, duration]` を探索する（`latency` は 4.7 の STFT 群遅延補正）。これにより、窓のすぐ外側にある強いオンセット（例: 120 BPM の半拍後のハイハット）が補正で窓内に引き込まれる誤検出を防ぐ。
2. 窓内の `onset_b` 最大フレーム `f*` を求める。最大値が `threshold` 未満なら `status = "undetected"`。
3. 放物線補間: `δ = 0.5*(y[f*-1]-y[f*+1]) / (y[f*-1]-2y[f*]+y[f*+1])`（分母 0 なら δ=0、|δ|>1 は 0 にクランプ）。
4. `tOnset = (f* + δ) * H / sampleRate + latency`
5. `deviationMs = (tOnset - T_k) * 1000`
6. `deviationBeats = (tOnset - T_k) / beatDur`
7. `strength = onset_b[f*]`

ずれの符号: **正 = 拍より遅い（後ろ）／負 = 拍より早い（前）**。

### 4.8 CSV 仕様

- 文字コード: UTF-8 BOM 付き、改行 CRLF（Excel 互換）。
- 区切り: 設定 `csvDelimiter`（`,` または `;`）。
- 小数桁: 設定 `csvDecimals`（時刻・ずれ・強度）。`deviation_beats` は +1 桁。
- ヘッダ（英語固定）:

```
band_index,band_label,frequency_range_hz,beat_index,bar,beat_in_bar,expected_time_s,onset_time_s,deviation_ms,deviation_beats,onset_strength,status
```

- 行の例: `1,Low,20-250,0,1,1,0.420,0.431,11.2,0.0239,0.814,detected`
- `status`: `detected` / `undetected`。`undetected` のとき `onset_time_s` 以降は空。
- `includeUndetected=false` なら `undetected` 行を省略。
- ファイル名既定: `{audio_stem}_band{index+1}_{label}_beats.csv`（英数字・`-`・`_` 以外は `_` に置換）。
- 出力先は保存ダイアログで選択。キャンセル時は `{ "canceled": true }`。

## 5. IPC 仕様（Tauri コマンド）

すべて `invoke("<name>", { ... })`。エラーは reject で `AppError`:

```json
{ "code": "ERR_AUDIO_TOO_SHORT", "message": "Audio must be at least 5 seconds.", "params": { "min": "5.0", "actual": "3.2" } }
```

| コマンド | 引数 | 戻り値 |
|---|---|---|
| `app_info` | – | `{ version, dataDir, portable, webview2 }` |
| `pick_audio` | – | `{ path } \| { canceled: true }` |
| `load_audio` | `{ path }` | `AnalysisResult` |
| `reanalyze` | `{ path?, fftSize? }` | `AnalysisResult`（音声は再デコード） |
| `set_bands` | `{ bands: [{lowHz,highHz,color}], fftSize? }` | `{ bands: [...] }`（エンベロープ/オンセットのみ再計算。fftSize 変更時は再解析） |
| `pick_project` | – | `{ path } \| { canceled: true }` |
| `load_project` | `{ path }` | `LoadedProject` |
| `save_project` | `{ project }` | `{ path } \| { canceled: true }` |
| `load_settings` | – | `Settings` |
| `save_settings` | `{ settings }` | `{ ok: true }` |
| `export_beats_csv` | `{ bandIndex, tempo, tolerance?, includeUndetected?, delimiter?, decimals? }` | `{ path, rows, detected, canceled? }` |
| `export_beats_csv_to` | 上記 + `{ path }`（テスト/自動化用） | `{ path, rows, detected }` |
| `play` / `pause` / `stop` | – | `{ ok: true }` |
| `seek` | `{ seconds }` | `{ ok: true }` |
| `set_volume` | `{ volume }` | `{ ok: true }` |
| `playback_state` | – | `{ positionSec, durationSec, playing, volume, ended }` |
| `open_path` | `{ path }`（外部起動用） | `{ ok: true }` |
| `reveal_file` | `{ path }` | `{ ok: true }` |
| `quit` | – | – |

- `analysis-progress` イベント: `{ phase: "decode" \| "fft" \| "bands", progress: 0..1 }` を 100ms 間隔で emit。
- `playback_state.ended`: 再生位置が末尾に達して停止したら true（UI は先頭に戻す）。
- `open_path`: 起動引数 `--open` / ドラッグ＆ドロップで使用。

補足（実装上の確定事項）:

- `LoadedProject` = `{ "project": ProjectFile, "audioMissing": true|false }`
- `startup_args` コマンド → `{ "openPath": string|null, "projectPath": string|null }`（起動時に UI が一度呼ぶ）
- `set_bands` の戻り値 = `{ "bands": BandResult[] }`（`BandResult` は 3.2 と同じ。`index/label/lowHz/highHz/color/envelope/onset`）
- 追加エラーコード: `ERR_TEMPO_REQUIRED`（CSV 出力時にテンポ未設定）、`ERR_NO_AUDIO`（音声未読込）、`ERR_CANCELED`（解析の世代交代）

### 5.1 CLI

```
NamiVision.exe [--open <audio>] [--project <file>] [--portable] [--selftest [--selftest-dir <dir>]]
```

- `--selftest`: GUI を起動せず、合成音声を生成→解析→CSV→JSON 往復を実行し、結果を標準出力と `selftest_report.json` に書き出して終了コード 0/1。
- リリースビルドは `windows_subsystem = "windows"` だが、`--selftest` 指定時は `AttachConsole` を試み、失敗してもファイル出力で確認可能。

## 6. UI 仕様

### 6.1 画面構成（上から）

1. **アプリヘッダ** (48px): ロゴ＋`NamiVision`、ファイル名チップ（未読込時は "No audio"）、右側に「開く」「プロジェクト」「設定」「ヘルプ」。
2. **トランスポートバー** (56px): 再生/一時停止（主ボタン）、停止、シークバー（現在/全体、ドラッグ可）、`00:12.34 / 03:33.45`、音量スライダー、テンポチップ（`128 BPM · 4/4`／未設定は `Tempo not set`、クリックでダイアログ）。
3. **タイムルーラー** (28px): 時間目盛り（適応間隔: 0.1/0.2/0.5/1/2/5/10/30/60s）＋小節番号。再生ヘッドのハンドル。小節開始フラグ（テンポ有効時）。
4. **レーン領域**（残余高さ、縦スクロールなし・横スクロール）:
   - Master レーン（高さ 34%、最小 96px）: 全体波形＋グリッド＋再生ヘッド。
   - バンドレーン × bandCount（残りを均等割り、最小 56px）: 帯域エンベロープ、帯域ラベル、Hz 範囲、色。
   - 左に固定レーン見出し列（幅 88px、倍率連動）: `MASTER`、`LOW 20–250` など。
5. **ステータスバー** (28px): サンプルレート・ch・長さ・解析時間・ズーム・選択レーン・ショートカットヒント。

- 空状態: レーン領域中央にドロップゾーン（点線枠、アイコン、`音声ファイルをドロップ`、対応形式、5 秒以上の注記、「ファイルを開く」ボタン）。
- 解析中: 進行バー付きオーバーレイ（キャンセル不可、進捗 %）。
- 音声消失バナー: プロジェクト読込時に音声が見つからない場合、ヘッダ下に警告バー＋「再選択」。

### 6.2 ビジュアル（デザインコントラクト）

- 方向性: 「計測機器としてのスタジオ UI」。装飾ではなく精度・階層・一貫した計測色。
- ダーク（既定）: canvas `#0E1116` / surface `#151A21` / surface-2 `#1B222B` / rule `#26303C` / ink `#E8EDF4` / muted `#93A1B3` / action `#FFB74D`（文字は `#201603`）/ focus `#6FB3FF`
- ライト: canvas `#F5F4EF` / surface `#FFFFFF` / surface-2 `#EFEDE6` / rule `#D8D5CB` / ink `#1B1F24` / muted `#5E6773` / action `#B26A00` / focus `#0B62C4`
- 帯域色（両テーマ共通、コントラスト確保のため線は不透明・面は 22% 透過）: Low `#4FC3F7`、Low-Mid `#7BD88F`、Mid-High `#FFC857`、High `#FF7A8A`。Master 波形は `#E8EDF4`（ダーク）/`#232A33`（ライト）＋アクセント。
- タイポ: UI = `"Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`、数値 = `"Cascadia Mono", "Consolas", ui-monospace`。本文 13px、見出し 15/20px、数値 12–13px。すべて rem 指定で倍率に追従。
- 形状: 角丸 6px（ボタン）/10px（パネル）、境界は 1px hairline、影はモーダルのみ。グラデーション装飾なし。
- シグネチャ: ルーラー上の琥珀色の小節開始フラグと、帯域ごとに色分けされた 4 本のレーン。
- モーション: 150ms のフェード/スライドのみ。`prefers-reduced-motion` で無効化。

| Esc | メニュー/ダイアログを閉じる |
| Tab / Shift+Tab | フォーカス移動（可視フォーカスリング） |

- 右クリックメニューは独自 HTML。画面端で反転。外側クリック/Esc/メニュー項目選択で閉じる。`role="menu"`、項目は `role="menuitem"`、disabled は `aria-disabled="true"`。
- テンポ未設定時の CSV 項目は `disabled` で、理由をメニュー下部に小さく表示（`先に BPM と拍子を設定してください`）。

### 6.4 ダイアログ

**テンポ設定**: BPM（数値入力＋−/＋、Tap Tempo）、拍子（2/3/4/6/8 セグメント）、小節開始（秒入力＋「再生ヘッド位置を使用」）、分割表示（1/2/4）、グリッド表示・スナップのトグル、キャンセル/適用。適用で `enabled=true`。
**設定**: 左ナビ（一般 / 再生 / 解析 / 出力 / 情報）。
- 一般: 言語（日本語/English）、テーマ（ダーク/ホワイト）、UI 倍率（80–150%、5% 刻み、ライブプレビュー）。
- 再生: 音量、波形ゲイン、再生ヘッド追従。
- 解析: FFT サイズ（1024/2048/4096、変更時は再解析）、帯域数（1–4）、帯域境界（3 つの数値入力、昇順バリデーション）、感度。
- 出力: 区切り文字（`,`/`;`）、小数桁（0–6）、未検出行を含める。
- 情報: バージョン、データ保存先、ポータブル状態、ライセンス。
- 設定変更は即時反映＋400ms デバウンスで保存。ダイアログは Esc / 背景クリックで閉じる（変更は保持）。
**CSV 出力結果**: トースト `CSV を出力しました（N 行 / 検出 M）`＋「フォルダを開く」。

### 6.5 i18n

- `ui/js/i18n.js` に `ja` / `en` の完全な辞書。`data-i18n` / `data-i18n-title` / `data-i18n-aria` 属性で適用。
- 動的文言は `t(key, params)`。欠損キーは英語→キー名の順でフォールバックし、開発時はコンソール警告。
- 数値・時刻は `Intl.NumberFormat(lang)`。CSV ヘッダは英語固定（仕様 4.8）。
- 言語切替は即時（再読込なし）。`document.documentElement.lang` も更新。

### 6.6 スケール

- `document.documentElement.style.setProperty('--scale', scale)` と `fontSize = 14 * scale + 'px'`。
- レイアウトは rem / flex。キャンバスは CSS サイズ×DPR で描画し、文字サイズは `13 * scale`。
- 倍率 150% で 900px 幅でも操作不能にならないこと（ヘッダは折り返し、ラベルは省略記号）。

### 6.7 テーマ

- `<html data-theme="dark|light">`。CSS 変数で切替。キャンバスは描画時に変数を読む。
- 起動時は設定値。`prefers-color-scheme` は初回既定（未保存時）のみ参照。

### 6.8 アクセシビリティ

- すべてのボタンに `aria-label` または可視テキスト。アイコンのみのボタンは `title` も付与。
- フォーカスリング 2px。キーボードのみで「開く→再生→テンポ設定→CSV 出力」が可能。
- 色だけで状態を伝えない（再生状態はアイコン＋テキスト、帯域はラベル＋色）。
- コントラスト比 4.5:1 以上（本文）、3:1 以上（大文字・境界）。

## 7. 安定性・エラー処理

- Rust 側は `unwrap()` / `expect()` を本番経路で禁止（テストと起動時のみ許可）。`Result` を伝播。
- 解析は `spawn_blocking` で実行し UI をブロックしない。解析中の再読込は前処理をキャンセル扱い（世代番号で古い結果を破棄）。
- 巨大ファイル: 20 分超で警告、60 分超で拒否。ピーク列・バンド行列のメモリ上限を事前計算し、超過時は `ERR_MEMORY_LIMIT`。
- デコード失敗・部分破損: エラーコード `ERR_DECODE`（詳細付き）。無音ファイルは解析成功（波形 0）。
- 再生デバイスなし: `ERR_AUDIO_DEVICE`。UI は解析・CSV を継続可能。
- 保存失敗（書込不可・パス不正）: `ERR_WRITE`。UI はトーストで通知し状態を壊さない。
- 設定/プロジェクト JSON 破損: 既定値へフォールバックし、破損ファイルは `.bak` に退避して通知。
- 終了時: オーディオスレッドへ Stop→join、設定をフラッシュ。
- 二重起動・連打: コマンドは冪等 or 状態ガード。CSV 出力中の再実行は無視。

## 8. 試験計画

### 8.1 Rust 単体テスト

- `dsp`: 対数バンド境界（単調増加・20/20000Hz）、バンド→ビン集約、エンベロープ正規化、オンセット（無音=0、インパルスで正）、放物線補間（既知のピーク位置）。
- `beats`: 拍時刻・小節番号（負の拍を含む）、探索窓、検出/未検出、符号、CSV（BOM/CRLF/区切り/小数桁/エスケープ/未検出行）。
- `decode`: 生成 WAV（正弦波・クリック）のメタ情報、5 秒判定、チャンネル変換、非対応拡張子。
- `project`: JSON 往復、既定値補完、版エラー、帯域クランプ、設定クランプ、ポータブルパス。
- `playback`: 位置/音量の Atomic 更新、末尾到達で `ended`（デバイスなし環境ではロジックのみ）。

### 8.2 統合セルフテスト（`--selftest`）

1. 120 BPM・4/4 のクリック列（キック 60Hz、スネア 200Hz+ノイズ、ハイハット 8kHz）を 12 秒生成。
2. 拍頭から +15ms 遅らせたキック、-8ms 早めたハイハットを混在。
3. 解析→帯域ごとの CSV 出力→ずれの中央値が期待値 ±5ms であることを検証。
4. プロジェクト JSON 保存→読込→主要フィールド一致を検証。
5. 5 秒未満 WAV が `ERR_AUDIO_TOO_SHORT` になることを検証。
6. レポートを JSON で出力。

### 8.3 UI テスト（ブラウザ・モックバックエンド）

- 1440×900 / 1024×700 / 900×600、倍率 80/100/125/150%、ダーク/ライト、ja/en。
- 空状態 → 読込 → 再生 → テンポ設定 → CSV 出力 → 設定変更 → プロジェクト保存/読込の一巡。
- 右クリックメニューの disabled 状態、画面端での反転、Esc 復帰。
- キーボードのみでの主要操作、フォーカス可視性。
- コンソールエラー 0、レイアウト崩れ（重なり・切れ・横スクロール）0。

### 8.4 実アプリ QA

- リリース exe 起動→音声読込→再生→CSV→JSON→終了。プロセス残存なし。
- WebView2 不在時のメッセージボックス（コードパス確認）。
- ポータブルモードで `data/settings.json` が作られること。
