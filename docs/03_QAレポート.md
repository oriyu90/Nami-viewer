## 3. 検証方法

1. **Rust 単体テスト** — デコード、STFT、帯域エネルギー、オンセット検出、拍グリッド、CSV、プロジェクト JSON、設定、CLI、エラー。
2. **フロントエンドテスト** — 拍ずれ計算、CSV 生成、i18n 辞書の整合、数値書式、DOM 非依存ロジック。
3. **内蔵セルフテスト** — 既知のオフセットを持つクリック音源を生成し、解析→拍検出→CSV→プロジェクト往復→短尺拒否までをヘッドレスで実行。
4. **実アプリ E2E** — リリース版を起動し、WebView2 の CDP（puppeteer-core）で UI を操作。ファイル保存／読込は `winapp ui`（UI Automation）でネイティブダイアログを操作。
5. **表示検証** — 1282×780 CSS（100%）と 900×約 700 CSS（150%）で、ダイアログ・メニュー・ルーラー・レーン見出しの収まりをスクリーンショットで確認。
6. **配布物検証** — zip を別フォルダへ展開し、`--selftest`、`app_info`、音声読込、CSV 出力、再生を実行。

### 4.3 内蔵セルフテスト（`--selftest`）

12 チェックすべて合格。既知オフセットを付けた 120 BPM・12 秒のクリック音源を使用。

| 項目 | 結果 |
|---|---|
| Low 帯の中央値 | **+16.21 ms**（期待 +15.00 ms、誤差 +1.21 ms） |
| Low-Mid 帯の中央値 | **+6.78 ms**（期待 0.00 ms） |
| High 帯の中央値 | **−5.56 ms**（期待 −8.00 ms、誤差 +2.44 ms） |
| 拍検出数 | **23 / 24**（Low / High とも） |
| 解析フレーム | 1,030 フレーム / 96 対数帯域 / 12.0 秒 / 44.1 kHz |
| CSV 構造 | BOM あり・ヘッダーあり・CRLF・検出行 23 |
| プロジェクト往復 | BPM 120 / 小節開始 0.5 / バンド 4 / zoom 128 / lang en / 音声欠落 false |
| 短尺音声 | `ERR_AUDIO_TOO_SHORT`（actual 3.0 秒）で拒否 |

誤差は Low / High とも仕様上の 5 ms 基準を満たす。Low-Mid の +6.78 ms は帯域フィルタの位相特性とオンセット定義に由来する系統差で、30 ms の実用許容内。

リリース版の実アプリで読み込みを確認。

| ファイル | 形式 | サンプルレート / ch | 長さ | 結果 |
|---|---|---|---|---|
| `click_120bpm.wav` | WAV PCM 16-bit | 44.1 kHz / 2 | 12.000 s | 合格（1,030 フレーム） |
| `click_120bpm_48k_mono.wav` | WAV PCM 16-bit | 48 kHz / 1 | 12.000 s | 合格（1,122 フレーム） |

### 4.5 拍ずれ精度（実アプリ・4 バンド CSV）

120 BPM・4/4・小節開始 0.5 秒で、4 バンドを実アプリから CSV 出力した結果。

| バンド | 行数 | 検出 | 中央値 | 最小 | 最大 | 外れ値（±100 ms 超） |
|---|---|---|---|---|---|---|
| Low (30–200 Hz) | 24 | 23 | +16.45 ms | +7.27 ms | +22.92 ms | **0** |
| Low-Mid (200–900 Hz) | 24 | 23 | +7.76 ms | +0.88 ms | +9.53 ms | **0** |
| Mid-High (0.9–3.5 kHz) | 24 | 23 | −2.54 ms | −6.23 ms | +0.68 ms | **0** |
| High (3.5–15 kHz) | 24 | 23 | −5.59 ms | −7.32 ms | −1.04 ms | **0** |

- 先頭拍（t=0）は解析窓が音声先頭に掛かるため未検出となる（24 行中 1 行が `undetected`）。CSV には `includeUndetected` 設定に従って空の測定値行として残る。

## 7. 既知の制限と注意事項

1. **拍検出はヒューリスティック** — オンセット強度の閾値と ±0.45 拍の探索に基づく。クリック音源では 23/24 と高精度だが、複雑な楽曲・弱いアタック・ノイズでは未検出や誤検出があり得る。感度は設定で調整可能。
2. **先頭拍（t=0）は未検出になりやすい** — 解析窓が音声先頭に掛かるため。CSV には未検出行として残る。
3. **BPM の自動検出は無い** — 仕様どおり手入力またはタップテンポ。拍子・小節開始も手動設定。
4. **ずれ値の分解能は解析設定に依存** — FFT サイズ 2048（44.1 kHz で約 46 ms 窓）とパラボリック補間を使用。クリック系では数 ms の精度だが、実演奏では帯域フィルタの位相特性により帯域間で系統差が出る（Low-Mid で約 +7 ms）。
5. **音声は 5.0 秒以上 3600 秒以下** — 1200 秒超は長尺警告を表示。5 秒未満は明示エラー。
6. **ポータブル設定の保存先** — `<exe>\data` が書き込めない場合、`%TEMP%\namivision-data` へフォールバックする。設定を確実に保持するには書き込み可能なフォルダへ展開する。
7. **WebView2 ランタイムが必要** — Windows 11 は標準、Windows 10 も Edge 更新で通常導入済み。未導入環境では起動時に案内を表示する。
8. **900 CSS px / 150% ではファイル名チップが省略表示** — 長いファイル名は末尾省略（`…`）。機能上の影響は無い。
9. **UI 倍率の検証範囲は 100 / 125 / 150%** — 200% は未検証（物理 200% DPI 環境で論理サイズを変えて検証）。
10. **Windows 11 実機は未検証** — Windows 10 22H2 で全機能を確認。WebView2 と Win32 API のみに依存し、OS 固有分岐は無い。
11. **MP3 の長さはコンテナ由来の誤差を含む** — デコード後のサンプル数で再計算するため、表示は実音声長に一致する（例: 12.042 秒）。
12. **同時に開ける音声は 1 つ** — 複数音源の比較はプロジェクトを切り替えて行う。

## 10. 結論

NamiVision 0.1.0 は、要望された計測・再生・出力・設定・ポータブル配布の各機能を満たしている。自動テスト 120 件（Rust 75 + フロント 33 + セルフテスト 12）と実アプリ E2E はすべて合格し、修正した 6 件の不具合も再検証済み。

残る制限は、拍検出がヒューリスティックであること、先頭拍が未検出になりやすいこと、BPM が手動設定であることなど、仕様上の割り切りに由来する。実運用では複雑な音源に対して感度調整と CSV の `undetected` 行の確認を推奨する。
